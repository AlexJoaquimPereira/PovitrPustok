## Upgrade test

Previous release: **v1.2.2** (tag `cfeddc2`, versionCode 8, APK Signature Scheme v2, same signer
certificate). The published v1.2.2 asset is not anonymously reachable because the repository is
private, so the test used a release build from the `v1.2.2` tag with the release keystore and the
private corpus. The published asset's SHA-256 is
`5bfda0b39e06c8f65d8240dbd3aa06d15d32812be51b90f73e9328eef1bbafe1` for reference.

Procedure and result:

1. Uninstalled the app, installed the v1.2.2 release APK on the API 35 emulator.
2. Opened **Bible → Utpoti (Genesis) → chapter 1**; the reading state was recorded.
3. Selected verse 1 and added a bookmark (`Bookmarked · Utpoti 1:1`).
4. Confirmed the bookmark was listed on the Bookmarks screen.
5. Installed the current 1.2.4 APK over it with `adb install -r` (no uninstall, same applicationId,
   versionCode 10 over 8).
6. Launched the app: the home screen showed **Continue reading — Utpoti, Just now**; Bookmarks still
   listed **Utpoti 1:1**; opening it returned to Genesis 1 with **Remove bookmark** shown.

**Result: pass.** The v2→v3 signing change and the Room v2→v3 anchor migration preserved both user
data tables on a real in-place upgrade.

## Release-gate findings

- **Repository is private (owner decision, 2026-10-28).** Anonymous download URLs return 404;
  Obtainium requires a GitHub token with read access (fine-grained: Contents: Read). Repository
  history contains no `.sqlite`, corpus XML, keystore, or secret blobs, so this is access control,
  not corpus protection.
- **Signing-key backup confirmed (2026-10-28).** The owner confirmed two offline encrypted backups
  of the release JKS/passwords and a tested restore. The key itself remains outside the repository.
- **No published checksums exist for earlier releases.** This dry run adds `SHA256SUMS`; future
  releases must attach it.
- **Earlier releases use generic asset names** (`app-release.apk`/`.aab`) and v2-only signatures.
  The packaging script now uses versioned names and v3 signing.
